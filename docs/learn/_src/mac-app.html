Same code, a Mac app

The DMG doesn't contain a rewrite. It contains the exact dist/ folder that Cloudflare serves, plus a small Chromium-based shell that serves it from inside the app.

What Electron is

Electron bundles two things into a .app: Chromium (the engine inside Chrome, which draws pages) and Node.js (which can touch the Mac: menus, files, notifications). Slack, VS Code, Discord and Obsidian are built the same way. That's why the DMG is about 115 MB even though our own code is small: most of it is a private copy of Chromium.

An Electron app has two kinds of process, and the split is the key to its security:

Why so strict? The page loads YouTube embeds and radio streams from the internet. If the page could call Node directly, a bad script could read your files. contextIsolation, sandbox and no nodeIntegration keep Node out of the page. A YouTube embed is a cross-origin frame. It does not see window.desktop. This app does not set nodeIntegrationInSubFrames, so the embed does not get the preload either. The app's own page can call setStatus, attention and release. setStatus is cut to 64 characters in the preload. Main strips control characters and bidi characters and cuts it to 64 again.

How dist/ gets into the app

  1. npm run dist in desktop/ first runs the normal web build, producing dist/, the same folder Cloudflare gets.
  2. electron-builder copies dist/ into Kitestring.app/Contents/Resources/web/, packs our .cjs files into an archive, adds the icon, and wraps it all in a DMG.
  3. At launch, main.cjs registers a private web address, app://custom-pomodoro/, and answers it from that web/ folder (desktop/protocol.cjs). It reads security headers from the same _headers file. It sends the content security policy and X-Content-Type-Options. When the file has them, it also sends X-Frame-Options, Referrer-Policy, Permissions-Policy and Cross-Origin-Opener-Policy. It leaves out Strict-Transport-Security and both Cache-Control rules.

Why a made-up app:// address and not just opening the file?

file:// can count as a secure context, the same family as https. This app still does not open its files that way. main.cjs registers app:// as a standard, secure scheme, with fetch, CORS and streams. The page then behaves like a real site, with no network and no server.

Why it doesn't die when Chrome closes

  • It isn't Chrome. It has its own Chromium, so quitting Chrome doesn't touch it.
  • Closing the window only hides it. main.cjs catches the window's close event and calls hide() unless a quit is already underway. ⌘Q, Quit in the app menu, Quit in the Dock, and Quit on the tray icon all quit for real.
  • Hidden doesn't mean slowed down. backgroundThrottling: false stops Chromium from slowing timers in a hidden window, so the countdown and the alert stay on time. The sound is your alert sound. The default is the signature chime.

Its own DNS, so YouTube stations play

The app uses system DNS by default. Settings > Extras can save a user-supplied HTTPS DNS endpoint on this Mac only. That option stays out of sync and exports. YouTube Music frames pass. Claude FM is allowed as a live channel. Lofi Girl and Chillhop are allowed as a live channel and as one pinned video each. Any other YouTube frame is cancelled before it loads. The filter only looks at frame loads. Scripts, XHR, images and media are left alone. The rule lives in desktop/youtube-policy.cjs with its own tests.

Trade-offs

About 115 MB for a timer is heavy. A native Swift app would be a few MB, and it would mean rewriting the whole UI. A lighter shell like Tauri uses the Mac's built-in Safari engine, which is smaller but behaves differently from Chrome for audio and YouTube embeds. Electron won because the exact same dist/ runs unchanged. Another trade-off: the app is signed "ad hoc" (no paid Apple developer certificate), so macOS may ask you to right-click → Open the first time.
