A six-part walkthrough of your own app

Inside Kitestring

You use it every day. These pages show what it's made of, where each piece runs, where your data lives, and why it was built this way and not some other way.

The whole lesson hangs on one picture. Learn this one and every page after it is a zoom into one box.

Three ideas to carry through every page

  1. The app is just files. After the build there's no "server program" running your timer. The timer, tasks, sounds and stats are JavaScript running inside a browser engine.
  2. The browser is the main computer. Your data's first home is the browser's built-in database, IndexedDB. The cloud is an extra copy for syncing, not the boss. People call this local-first.
  3. Everything else is a thin helper. Each helper does more than one extra. The companion serves the files on this Mac and can ring when Chrome is closed. Access signs you in. The Worker checks that token and reads and writes the sync database. The shell stays in the menu bar, serves the files at app://, sets DNS-over-HTTPS, and filters YouTube frames.
