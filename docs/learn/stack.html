Lesson 1 of 6

The stack

"Stack" just means the list of tools the app is built from. Kitestring's list is short on purpose: two runtime libraries and a handful of build tools.

Start with what you see

When you press Start, a ring fills and a clock counts down. Rain stays off until you turn it on. When the session ends, your alert sound plays and a notification pops up. The default sound is the signature chime. Bell is one of the other voices. 25 minutes is the default length only in pomodoro mode. Every one of those things is frontend code: code that runs on your machine, inside the browser engine, and draws the screen.

Backend means code that runs on some other computer and answers requests over the network. Most apps you know (Notion, Gmail) are mostly backend: the real work and the real data live on their servers, and the page is a window onto them.

Kitestring is the other way round. Nearly everything is frontend. The backend is worker/index.ts, about 130 lines. Much of that file checks the login token and answers /api/me. The sync routes are the part that keeps a copy of your data.

The tools, one by one

ToolWhat it isWhat it does here
TypeScriptJavaScript with typesCatches many mistakes before the app runs, such as passing the wrong kind of value into a function. Minutes and milliseconds are both plain numbers here, so that mix-up gets through. The browser never sees TypeScript. The build turns it into plain JavaScript.
React 19A UI libraryYou describe what the screen should look like for a given state ("timer running, 12:04 left"), and React updates only the parts that changed. It and react-dom are the only two runtime dependencies.
Vite 8A build tool and dev serverIn development it reloads instantly as code changes. npm run build bundles everything into the dist/ folder: two HTML files (the Vite entry index.html, and research.html copied from public/), a few hashed JS and CSS files, plus sounds and images.
Web Audio APIBuilt into every browserMakes the noise generators, the 16 Hz focus modulation, the mixer and the end-of-session alert. No audio library, just the browser.
IndexedDBA database built into every browserStores tasks, stats, notes and settings on your machine. Lesson 3 covers it.
VitestA test runner282 tests check the timer maths, the Focus Score, backup validation, store saving and so on. Run them with npx vitest run. The root package.json has no test script.

What's deliberately missing

No UI kit (Material, Tailwind components), no state library (Redux, Zustand), no router, no analytics. Each would add code you don't control and data you might not want sent anywhere. State lives in a small homemade store, src/lib/store.ts, about 200 lines. It saves to IndexedDB and keeps open tabs in step.

How a click becomes a sound

Here's the real path when you press Start, so the words above have something to hang on.

  1. FocusView.tsx (React) calls timerActions.toggle(). start() runs inside timer.ts when the timer was not already going.
  2. timer.ts stores a start time (startedAt), time already elapsed (elapsedBefore), and the session length. Elapsed time is elapsedBefore plus, while running, now minus startedAt. Remaining time is the length minus that. A sleeping tab can't lose time, because nothing is counting ticks. After a pause, startedAt is empty, so remaining time stays at length minus elapsedBefore. The clock can move while you are paused, and that gap is not subtracted.
  3. The store saves itself to IndexedDB and tells other open tabs.
  4. syncAudio() asks Web Audio to play your alert sound when the seconds left run out, on the sound card's own clock. The sound is settings.timer.alertSound. The default is "signature". If the companion is up, the page cancels its own chime so you hear the alert once.
  5. Every 250 ms a ticker redraws the digits. If that ticker gets throttled, the display lags but the alert still plays on time.
Where "no backend" stops being true

Three jobs can't be done from inside a browser tab: ringing after Chrome is quit, proving who you are to a server, and living in the menu bar. Each of those got a small helper outside the browser. The next lessons are about those helpers.

Check yourself

The timer stores a start time, time already elapsed, and a length. It does not store "seconds left". Suppose you start a fresh 25-minute session, close the laptop lid for 10 minutes, and open it again. What does the screen show, and why would a "seconds left" counter get it wrong?

Show the answer

It shows about 15 minutes left. On wake the app computes start + 25:00 − now, and "now" is 10 minutes later. A "seconds left" counter that subtracts 1 each tick would have been frozen while the Mac slept, so it would still say about 25 minutes. Storing a timestamp makes sleep, throttled tabs and reloads harmless.
